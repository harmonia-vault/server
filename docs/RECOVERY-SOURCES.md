# 完整恢复的历史来源图

本切片在已公开的原初始化锚基线上扩展服务端恢复响应。恢复种子、分用途派生、一次 nonce 持钥证明、受限会话及新码完整重输轮换沿用原协议，没有新增原语，也没有将私有恢复钥发送到服务端。

## 明确请求与返回

`GET /v1/accounts/:id/recovery-vault?capability=issuer-origin-v1` 额外返回：

```ts
{
  originalInitialization: OriginalInitialization | null;
  issuerEvidence: IssuerOriginProofV2 | null;
}
```

请求仍须当前代际的受限恢复会话，或逐环境全部当前 Admin 的可信设备会话。恢复会话已证明持当前恢复签名钥；它不因获得这个响应而成为受信设备。请求仍检查会话期限与恢复代际。旧不带 capability 的 DTO 不加这些字段，不改变原行为。

缺原初始化记录的旧夹具明确返回两个 null，不补造根；客户端必须拒绝以它们恢复信任。原记录存在时，缺必要来源、签名历史、归档身份或不一致的已接受事件均拒绝，不能只返回可恢复的一部分环境。

## 所有现存环境的验证入口

图沿用 `harmonia/issuer-proof/v2`，主身份路径是原根的空路径；其他历史管理者和写入者都必须有原根到该设备的真实双签归档路径。根公钥元组保持不变。先验证原初始化的设备及原恢复双签，再以其中精确初始 grant 摘要集合作为 genesis；目录、当前 selfGrant 或仅 null 历史不能建立新初始权源。

每个现存环境的当前 keyVersion 有且仅有一个 target。它是历史核验的入口，角色可为 RO/RW/Admin，不能把它当成新设备的当前权限。服务端优先从该环境当前版本的非 none 签名授权选择；当前授权全部撤销或清空时，从同环境同版本已接受的非 none 历史中选最近的记录，同序号按精确授权摘要确定顺序。选择不要求设备仍存活或授权期限仍有效。

源集合还包含全部当前版本非 none 的 currentGrants、原初始化授权和每个实际返回变量事件在接受时冻结的写入授权。每个遇到的环境来源都展开完整 before/after 清单的精确签名授权和双签身份路径，并分别核操作者旧 Admin 与接收者旧权限。旧角色/期限只用于证明过去的合法来源，当前在线业务继续单独检查当前授权。

同一账号事务中，服务端比对原完整 EnvironmentChange 的控制字段、摘要、两个签名、接受序号、同批 grant 与旧父授权顺序，并验证每个返回变量签名与冻结授权的主体、版本、代际和写权限。来源图没有标签、变量名、变量数据密文或恢复封套；接收者 grant 中的 HPKE 封套只含已有设备的环境钥封装。恢复 DTO 的环境恢复封套和变量密文在图外供恢复客户端核验并解密。

所有设备已撤销、currentGrants 全为空、全部 none 或全部到期都不会阻塞历史恢复。原根设备记录可以 revoked；它只是固定身份元组，不授予当前 Admin。恢复图也不会让这些设备重新获得 boot、写入、管理或设备注册权限。

## 客户端顺序与限制

客户端应依次：用当前恢复码派生公钥核当前可信根；用相同的根 Ed/X 元组核原初始化设备签名，再核原恢复签名与完整 proposal 摘要；冻结原初始授权摘要；按该精确锚验证完整来源图；检查每个 target 对应现存环境当前版本；核每个写入者历史授权、签名和版本；再逐环境核对完整签名封套承诺，包括空环境，最后才用 HPKE 解封与 AEAD 解密当前密文。

完整恢复须额外请求 `envelopeEvidence=recovery-envelope-v1`；签包/完整轮换清单与原初始化封套的校验顺序见 [恢复封套承诺](RECOVERY-ENVELOPES.md)。HPKE 使用公开接收钥，成功不能独立证明钥匙来源。

响应中的 publicDevices 只用于显示，不得用它补写入者或管理者的可信公钥。缺图、缺任一来源或未知历史写入者必须拒绝。恢复成功仍处于受限会话，须显式完成新恢复码轮换；图的 target 不会绕过这个流程或自动注册新设备。

证据边界和账号 1 MB 容量沿用 [来源与 v3](ENROLLMENT-V3.md)。图最多 512 个授权节点、128 个来源证书、16 条辅助路径；单路径最多 32 项，总归档引用最多 128，规范编码最多 1 MB。超限拒绝，不裁剪来源或放宽密码/签名参数。线上配额与大历史容量尚未验收。

## 独立验证

新增 `test/recovery-origin.test.ts` 使用正式服务的双签原初始化、公开合成中继及成熟 Ed25519 签名，经真实 Node TCP 与 workerd HTTP 执行非根 B 新建 Y、C RW 入网写 Y、B 完整轮换 X，再撤销原根或全部设备。另验证全部当前授权 none/到期仍可历史恢复，缺源/归档/假 genesis/篡改签名与完整变更拒绝、旧代际和受限会话不能在线管理、SQLite 真 UPDATE 失败整笔回滚。测试中不使用宿主真实秘密，不发送邮件。

这些服务端测试的 HPKE/AEAD 封包是结构合成数据，不能代替客户端真实加解密联合验收；该验收由独立 Go 切片记录。此前公开的原初始化 17 项负例和 134 项基线不改写为新多环境正例。具体本轮通过/失败记录见 [测试记录](TESTING.md)。
