# 环境生命周期与设备撤销

这是实验性实现，尚不能宣称生产可用。环境名称、变量值和环境钥都不以明文交给服务器；测试材料只包含公开合成值。

## 当前接口

所有接口位于 `/v1/accounts/:accountId`，要求 HTTPS，以及 Bearer 设备会话、`X-Harmonia-Device-Id` 和 `X-Harmonia-Account-Generation`。密码登录产生的未绑定会话不能管理环境。每次请求都重查当前设备状态、会话、账号代际和权限。

| 方法与路径 | 行为 |
| --- | --- |
| `GET /environments` | 列出本设备当前可读环境、密文名称、版本和当前签名授权 |
| `POST /environment-changes` | 提交管理设备签名的创建、改名、删除或钥匙轮换操作 |
| `GET /environment-changes/:idempotencyKey` | 仅查询本设备发起操作的完成状态与序号，不暴露其他设备收据 |
| `POST /device-revocations` | 全环境 Admin 获取一次设备撤销挑战，请求包含目标设备和幂等键 |
| `GET /device-revocations/:idempotencyKey` | 查询本设备发起撤销的待完成/完成状态；结果不明时可先查询 |
| `POST /device-revocations/complete` | 提交完整挑战和设备签名，原子撤销目标设备 |

成功写入后客户端仍须使用与普通同步相同的持久序号拉取路径更新本地权威状态，不能凭 HTTP 成功在本地乐观修改。断网导致结果不明时先查询自己的操作收据。删除本次所据的管理环境后，原始 POST 的当前权限重查可能拒绝；完成收据仍可查询，不会将重试作为新写。

## 环境操作的安全边界

环境创建需要一个现有环境的有效 Admin 授权，显式签入该授权的环境、钥匙版本和授权代际。只能为创建者建立新环境的初始 Admin，且期限不得超过所据 Admin。创建须同时提供新环境恢复封套；恢复代际必须是账号当前代际。

改名与删除必须由该环境本身的 Admin 执行。名称是端到端密文；Go 的 `EncryptEnvironmentLabel` 使用独立附加数据域 `harmonia/environment-label/v1`，不能把名称密文冒充变量密文。用户显示名称前必须验证签名变更与已见检查点，并解密名称，不能把服务器的元数据当可信名称。

删除会移除当前环境、当前授权、存活变量密文和名称索引，保留管理设备签名的删除墓碑与已使用环境 ID。普通拉取及暂停期间的授权投影都应向曾获该环境授权的设备返回墓碑，即使当前授权已经移除。客户端验证墓碑后删除缓存及本地 override 的来源，再重算剩余环境并逐键恢复原值。历史签名记录与他人已经读取的密文、明文无法追回。

本轮拒绝删除最后一个环境，返回 `last_environment_requires_account_management`。原因是当前尚未定义独立、可核验的账号级管理授权；不能凭密码登录或服务器返回的根公钥字段偷偷提升权限。可先创建新环境，再删除旧环境，或在本机停用环境、清空变量。解除这个实验性门槛前，需要定义完整的账号管理授权链及对应安全测试。

## 环境钥匙轮换

客户端必须用安全随机源生成新独立环境钥，再创建以下完整清单：

1. 为每个当前有效设备生成新 HPKE 封套。角色和期限保持不变，授权代际加一，钥匙版本加一。
2. 为当前恢复接收钥生成新恢复封套，绑定当前恢复代际和新钥匙版本。
3. 把该环境当前全部存活变量重新加密，并逐项签名；已删除的变量不能重新出现。有名称时也须以新钥匙重加密名称。

所有清单与当前账号序号、所据管理授权及幂等键一起签入 `harmonia/environment-change/v1`。设备清单按设备 ID 的 ASCII 顺序，变量清单按变量名 ASCII 顺序，分别编码为固定字符串数组后 SHA256，摘要纳入外层签名。服务器只检查密文长度、签名、角色、版本和完整性；它不能解密或证明客户端确实选择了新随机钥。Go 使用既有成熟 XChaCha20Poly1305 和 RFC9180 HPKE 实现，不另造原语。

事务会先验证全部设备封套、恢复封套、存活变量名集合与签名，并检查 `expectedSequence` 等于当前序号。并发写入、授权变化或恢复变化会使旧快照失效，客户端须重新拉取后重建清单。缺任何必要元素或账号容量不足时整笔回滚。成功后旧钥匙版本立即不能写；新变更事件先取得一个序号，重加密变量随后分别取得序号。客户端发现新版本后完整补拉，避免漏掉新密文。过期或已撤销主体的最高授权代际仍保留，后续重授不能从一开始。

环境变更 HTTP 请求有 1 MB 硬上限，普通接口保持 100 kB，避免两项合法大密文的完整轮换被普通请求上限拒绝。当前单个账号文档也有 1 MB 容量边界，历史也计入容量。两项最大长度密文的轮换已实测因签名历史和幂等记录总量超出该容量而受控返回 503，整笔回滚；两项较大合法密文已通过超过 100 kB 的真实 HTTP 轮换。过大的完整轮换可能原子返回容量错误；这是本轮实验性规模限制，需要后续归一化存储和受签名检查点保护的历史整理来解除。

## 设备全局撤销

单个环境 Admin 不能撤掉目标设备在其他环境的权力。发起者须在所有现存环境都是有效 Admin。服务器生成 120 秒挑战，绑定账号及代际、发起者、目标设备的两种精确公钥、当前会话哈希、用途、幂等键、随机 nonce，以及全部环境的当前钥匙/授权代际。

完成时再次检查全部权限与挑战，只接受已注册签名钥的签名。同一事务标记目标设备撤销，删除其全部会话、设备/开机挑战与当前授权，并保存幂等完成收据。目标的后续请求立即拒绝；客户端收到账号认证或设备信任拒绝必须清相关缓存，不能把这些拒绝当作允许离线继续使用的普通网络故障。真正断网的设备只能在重新联网获知撤销；既有本地期限仍必须离线执行，已读明文不能追回。

## 本组件的实测证据

- 服务端 17 项合成安全测试通过：创建/改名/删除/完整轮换、缺项事务回滚、并发快照、角色/期限/代际边界、一次 nonce、旧会话失效、最后环境原子拒绝、跨语言签名向量，以及真实 HTTP 大密文轮换/请求上限与账号容量受控回滚。
- Go 新增 3 项测试通过，并通过 `go test -race ./cryptox`：共同向量、标签加密域隔离、空清单编码与数值边界。
- 服务端类型检查、构建及源码基础秘密/个人路径检查通过。
- 真实手机控制桥接和系统服务无人登录运行的验收由对应组件单独记录，本页不据此宣称完成。
